# STM32 超声波扫描雷达

基于 **STM32F103C8T6** 的二维扫描测距雷达：舵机驮着超声波模块在 0°~180° 之间来回扫描，
测得的距离经过滤波后实时绘制成 **OLED 极坐标雷达图**（扫描线 + 目标点 + 余晖拖尾）。

> 硬件平台：波特律动 keysking STM32 学习板 · 开发环境：STM32CubeIDE
> 全部代码基于 HAL 库与 CubeMX 配置，无 RTOS。

## 四、软件架构

### 文件结构

```
Radar/
├── Core/
│   ├── Inc/
│   │   ├── main.h
│   │   ├── oled.h / font.h        ← 显示驱动（见下方说明）
│   │   ├── tim.h / i2c.h / usart.h / gpio.h   ← CubeMX 生成
│   └── Src/
│       ├── main.c                 ← 全部应用逻辑
│       ├── oled.c / font.c        ← 显示驱动
│       └── tim.c / i2c.c / usart.c / gpio.c   ← CubeMX 生成
├── Drivers/                        ← STM32 HAL 库 + CMSIS
├── Radar.ioc                       ← CubeMX 工程配置
└── STM32F103C8TX_FLASH.ld          ← 链接脚本
```

> **关于 OLED 驱动**：`oled.c` / `font.c` / `oled.h` / `font.h` 来自
> [波特律动](https://www.baud-dance.com/)官方例程，用于驱动板载 CH1116 屏幕。
> **本项目的雷达扫描逻辑、状态机、滤波算法与雷达图绘制全部为本项目自行实现。**

### 主循环结构（全部非阻塞）

```
while (1)
{
  ├─ 1. 按键扫描        每 20ms 一次，检测下降沿
  ├─ 2. 页面切换        仅当页面号变化时才重绘静态页
  ├─ 3. 雷达扫描状态机   舵机 + 超声波联动
  │      ├─ 阶段 0：等待舵机机械停稳（100ms）
  │      └─ 阶段 1：连测 3 次 → 中值滤波 → 存表 → 下一个角度
  ├─ 4. 雷达刷新        脏标记触发，每次新数据重绘一帧
  └─ 5. 心跳            每 1000ms 翻转 LED + 串口打印
}
```

**没有任何一处使用 `HAL_Delay` 阻塞等待**（唯一的延时是 OLED 上电初始化，只执行一次）。
所有定时都基于 `HAL_GetTick()` 时间戳比较。

### 数据流

```
TIM1_CH3 捕获中断
      │  切换捕获极性，测出 ECHO 高电平宽度
      ▼
us_pulseWidth (µs)  ──►  距离(cm) = 脉宽 × 17 ÷ 1000
      │
      ▼
3 次采样  ──►  median3() 中值滤波  ──►  scanDist[19]
                                              │
                                              ▼
                                       radarDraw()  ──►  OLED_ShowFrame()
```

## 五、关键技术点

### 1. 单通道输入捕获测脉宽（中断内切换边沿极性）

测量 ECHO 高电平宽度，常见做法是用两个捕获通道分别抓上升沿和下降沿。
本项目只用 **TIM1_CH3 一个通道**，在中断回调里**切换捕获极性**：

```c
void HAL_TIM_IC_CaptureCallback(TIM_HandleTypeDef *htim)
{
    uint32_t cap = HAL_TIM_ReadCapturedValue(htim, TIM_CHANNEL_3);

    if (us_state == 0)   /* 抓到上升沿：记时间戳，改成等下降沿 */
    {
        us_riseTime = cap;
        us_state = 1;
        __HAL_TIM_SET_CAPTUREPOLARITY(htim, TIM_CHANNEL_3, TIM_INPUTCHANNELPOLARITY_FALLING);
    }
    else                 /* 抓到下降沿：算宽度，改回等上升沿 */
    {
        us_pulseWidth = cap - us_riseTime;
        us_done = 1;
        us_busy = 0;
        us_state = 0;
        __HAL_TIM_SET_CAPTUREPOLARITY(htim, TIM_CHANNEL_3, TIM_INPUTCHANNELPOLARITY_RISING);
    }
}
```

**优点**：只占一个通道、不需要从模式配置、中断里只读寄存器 + 置标志（微秒级返回）。
**为什么不用轮询**：`HAL_GetTick()` 精度只有 1ms，1ms 对应 17cm 误差；硬件捕获精度 1µs。

### 2. 非阻塞状态机替代顺序延时

顺序写法（**本项目未采用**）：

```c
for (角度 = 0; 角度 <= 180; 角度 += 10) {
    setServo(角度);
    HAL_Delay(100);   /* 死等舵机转到位 */
    HAL_Delay(60);    /* 死等测距 */
    HAL_Delay(30);    /* 死等推屏 */
}
```

每圈有 2.9 秒 CPU 纯空转，期间按键无响应、心跳停止。

本项目改为**时间戳判断 + 状态机**：主循环每圈只花几微秒检查"时间到了没"，
没到就直接跳过继续执行其他区块。**扫描全程按键、心跳、显示均正常响应。**

```c
switch (scanPhase)
{
  case 0:   /* 等舵机停稳 */
    if (HAL_GetTick() - scanTick >= SCAN_SETTLE_MS) { ... scanPhase = 1; }
    break;
  case 1:   /* 测距中，攒够 3 个样本就存表并换角度 */
    ...
}
```

### 3. 中值滤波抑制野值

HC-SR04 的波束角约 15°，在 50cm 处会覆盖直径约 13cm 的区域。
在多反射面环境下（显示器 / 桌沿 / 墙面同时存在），单次测量会在不同距离间跳变。

三次采样 `30 / 56 / 31`：

| 方法 | 结果 | 评价 |
|---|---|---|
| 平均值 | **39 cm** | ❌ 现实中不存在 39cm 的物体，野值污染了结果 |
| **中值** | **31 cm** | ✅ 野值被完全剔除，且不污染结果 |

**只要野值占比小于 50%，中值滤波就能完全剔除它；平均值做不到这一点。**

```c
static uint16_t median3(uint16_t a, uint16_t b, uint16_t c)
{
    uint16_t t;
    if (a > b) { t = a; a = b; b = t; }
    if (b > c) { t = b; b = c; c = t; }
    if (a > b) { t = a; a = b; b = t; }
    return b;                       /* 3 次比较完成排序，无函数调用开销 */
}
```

### 4. 查表法极坐标变换

把 `(角度, 距离)` 映射到 128×64 屏幕：

```c
x = CX - (RADAR_FLIP_X * rad * cosTab[idx]) / 1000;
y = CY - (rad * sinTab[idx]) / 1000;
```

**不用 `sinf()` / `cosf()`** 的原因：
- STM32F103C8T6 **没有 FPU**，浮点三角函数为纯软件实现，单次数十微秒
- 扫描只有 19 个固定角度，查表是 O(1) 且结果完全确定
- 省掉 `math.h` 与 libm 依赖，代码更小

### 5. 帧缓冲 + 整帧推屏

驱动维护一张 128×64 的显存位图：

```c
OLED_NewFrame();     /* 1. 清空帧缓冲 */
/* 2. 用绘图函数往缓冲里画（此时屏幕还没变化） */
OLED_ShowFrame();    /* 3. 一次性通过 I2C 推送整帧 */
```

推一整帧 = 1024 字节，400kHz I2C 下约 **20~30ms**。
若每画一笔就推一次屏，扫一圈会退化成幻灯片。
因此本项目用**脏标记**控制刷新：只在拿到一个新距离值时才重绘一帧，约 280ms 一次。

### 6. 带裁剪的绘图函数

驱动的 `OLED_DrawLine()` 参数是 `uint8_t`。
极坐标变换会算出**负坐标或超过 127 的坐标**，直接传入会**回绕成 255 并越界写坏显存**。

因此本项目自己封装了一层带裁剪的画点/画线：

```c
static void radarPixel(int x, int y)
{
    if (x < 0 || x > 127 || y < 0 || y > 63) return;   /* 越界直接丢弃 */
    OLED_SetPixel((uint8_t)x, (uint8_t)y, OLED_COLOR_NORMAL);
}
```

## 七、CubeMX 配置（复现用）

| 外设 | 参数 |
|---|---|
| **RCC / 时钟** | HSE 8MHz，PLL ×9 → SYSCLK 72MHz，AHB /1，APB1 /2（36MHz），APB2 /1（72MHz） |
| **SYS** | Debug = Serial Wire |
| **USART2** | Asynchronous，115200，8 位，无校验，1 停止位 |
| **I2C1** | I2C，Fast Mode，400000 Hz |
| **TIM4 CH3** | PWM Generation CH3，PSC = **719**，ARR = **1999**，Pulse = 150，PWM mode 1，Polarity High |
| **TIM1 CH3** | Input Capture direct mode，PSC = **71**，ARR = **65535**，IC3 Polarity = Rising，IC3 Selection = Direct TI3，IC Filter = 0 |
| **TIM1 NVIC** | 勾选 **TIM1 capture compare interrupt** |
| **GPIO** | PA6 / PA7 / PB0 = 输出（LED）；PA11 = 输出初始 Low（TRIG）；PB12 / PB13 = 输入上拉（按键） |

**两个关键数值的来历**：

- **舵机 50Hz**：`72MHz ÷ (719+1) = 100kHz`（每格 10µs），`(1999+1) 格 × 10µs = 20ms`
  → 脉宽数值含义：`70 ≈ 0°`、`150 = 90°`、`230 ≈ 180°`
  （**未使用理论的 50~250**，因为便宜舵机机械行程够不到两端，会顶在限位持续堵转、
  表现为大声嗡嗡响 + 发热 + 电流飙升；收窄到 70~230 后问题消失）

- **超声波 1µs 分辨率**：`72MHz ÷ (71+1) = 1MHz` → 计数值**直接就是微秒数**，
  距离换算无需任何缩放

## 八、踩坑记录

> 这一节记录开发过程中实际遇到并解决的问题，按发现顺序排列。

### 1. 串口一个字节都收不到，但 LED 正常闪

**现象**：程序明显在运行（LED 会亮），串口助手 `Rx = 0 Bytes`。

**排查**：先用 LED 确认程序存活 → 再用"闪一次还是反复闪"排除崩溃复位 →
逐文件核对 `_write` 重定向、`usart.c` 配置、`.cproject` 链接规格 —— 全部正确。

**根因**：所有 `printf` 都写在 `USER CODE BEGIN 2` 里（只执行一次），
上电后 4 秒内全部打完，之后进入空的主循环不再输出。
而串口助手是**之后**才打开端口的 —— **数据已经发完了，没人在听**。

**解决**：在 `while(1)` 里加"心跳"（每秒打印 + LED 翻转），
这样无论何时打开串口都能立刻看到输出。**心跳机制此后成为本项目的标准调试手段。**

### 2. `printf` 无输出

CubeIDE 生成的 `Core/Src/syscalls.c` 中，`_write()` 内部调用的 `__io_putchar()`
是一个**空壳函数**，什么都不发送。
需要在 `USER CODE BEGIN 4` 中重新实现 `_write()`，用 `HAL_UART_Transmit` 把数据发到 USART2。

### 3. I2C 地址 0x7A 还是 0x3D

板子图纸标注 OLED 地址 `0x7A`，但 I2C 扫描扫出来是 `0x3D`。

**原因**：I2C 传输时地址占**高 7 位**，最低位是读写标志。
- **7 位地址** = `0x3D`（设备真实门牌号，扫描得到的就是这个）
- **8 位地址** = `0x3D << 1 = 0x7A`（挪好位置准备发到总线的形式，驱动里用的是这个）

同一设备的两种写法。**教训**：HAL 库的 API 要求传 8 位地址，
所以扫描时手里拿着 7 位地址必须 `<< 1`，漏了就一个设备都扫不到。

### 4. 舵机持续嗡嗡响、外壳发热

**根因**：脉宽超出舵机实际机械行程，舵机顶在机械限位上**持续堵转**。

**解决**：把脉宽范围从理论的 `50~250` 收窄到 **`70~230`**，堵转消失。

**教训**：舵机堵转电流可达数百 mA，长时间堵转会烧电机或拉垮电源轨。
调试时如果发现舵机"一转就复位"，**先怀疑供电，别怀疑代码**。

### 5. 超声波读数在 30cm / 56cm 之间跳变

**现象**：同一位置，读数主要在两个值之间跳，偶尔出现第三、第四个值。

**定位过程**：把模块对准一面平整的墙、保持静止后读数**立即变稳** →
确认是**环境问题**而非传感器或代码问题。

**根因**：HC-SR04 波束角约 15°，在 50cm 处覆盖直径约 13cm 的区域。
桌面上同时存在显示器、桌沿、墙面、人体等多个反射面，
哪个回波先到（最强）就测到哪个。

**解决**：3 次采样取中值（见关键技术点 3）。
**这个是整个项目最有价值的调试经历** —— 它把一个"模块能跑就行"的 demo
变成了一个需要真正解决测量可靠性问题的工程。

### 6. 官方例程里的一处 bug

参考波特律动官方例程 `TIM_inputCapture` 时发现：

```c
upEdge   = HAL_TIM_ReadCapturedValue(htim, TIM_CHANNEL_3);   /* ✓ 上升沿 */
downEdge = HAL_TIM_ReadCapturedValue(htim, TIM_CHANNEL_3);   /* ✗ 应为 CHANNEL_4 */
distance = ((downEdge - upEdge) * 0.034) / 2;                /* → 恒等于 0 */
```

两行读取了同一个捕获通道，相减恒为 0，距离永远显示 `0.00cm`。
本项目改用**单通道切换极性**的方案，从设计上避免了这个问题。

### 7. 雷达图左右镜像

**现象**：雷达图上的扫描线方向与舵机实际转动方向相反。

**根因**：显示层约定"角度索引 0 画在屏幕左边"，而舵机的实际安装方向相反。

**解决**：加入一个明确的编译期开关，而不是散落地改坐标公式：

```c
#define RADAR_FLIP_X  (-1)   /* 1 = 索引0在左；-1 = 索引0在右 */
```

**教训**：硬件安装方向、传感器朝向这类差异，应该集中成一个**可配置的常量**，
而不是把符号散落在各个公式里 —— 否则下次换个舵机就要满地找负号。

## 九、如何编译运行

1. 用 **STM32CubeIDE** 打开工程（`File → Open Projects from File System`）
2. 确认 `Radar.ioc` 的外设配置与[第七节](#七cubemx-配置复现用)一致
3. `Ctrl + B` 编译
4. 用 ST-Link 下载（**建议用 Debug 模式**，方便随时 `Ctrl+F2` 停止）
5. 打开串口助手，连接板载 USB 串口，波特率 **115200**
6. 上电后应看到：

```
=== boot ===
=== I2C Bus Scan ===
  found 7-bit: 0x38   (8-bit: 0x70)
  found 7-bit: 0x3D   (8-bit: 0x7A)
=== scan done, 2 device(s) ===

angle=  0  d= 31 cm
angle= 10  d= 33 cm
...
```

**按键功能**：KEY1 切换页面（0 = 雷达图，1 = 绘图测试，2 = 按键说明）
